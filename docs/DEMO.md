# 十分钟演示：规则工作台＋负结果

适用源码候选、Python3.14。第一次安装不计十分钟；无需训练、GPU、Docker或历史权重即可完成第一段。

## 准备一次

```powershell
py -3.14 -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements/workbench.lock.txt
./.venv/Scripts/python.exe -m scripts.verify_delivery
./scripts/start_workbench.ps1 -PythonPath ./.venv/Scripts/python.exe
```

打开终端打印的本机URL（默认8765）。端口占用时加`-Port 8769`；同工作区已有服务会复用。首次启动会校验并安装真实样例，不覆盖不同内容的同ID历史。

## 0～4分钟：离线真实回放

1. “保存与回放”选择包含`0a2e84`的5步早春会话。顶部必须显示`HISTORY / 历史回放`，控制按钮禁用；这不是正在计算的新房间。
2. 点播放或拖动0～5。观察实测操作温度、实际供暖设定、电功率、耗电和角色状态；点击热泵查看热功率与电功率的区别。
3. 展开需求事件记录，解释冲突、撤销、26°C不可行、显式裁决和到期回基准；每个动作的需求快照版本独立保存。同刻新请求可出现在上一动作结束帧，不能把结束帧账本误认成该步控制输入。
4. 导出JSON，对照`examples/workbench/manifest.json`的原始摘要。离线复核命令重算5动作、155个区间点及官方KPI，不需要调用引擎。

## 4～7分钟：规则交互（可选，需已有BOPTEST）

引擎未部署时直接进入下一段，不把初始化失败当成离线回放失败。部署条件见[工作台说明](workbench.md)。

1. 返回实时，新建既有早春会话，默认按需求；提交A更暖/B更凉，看到冲突阻止推进。
2. 显式选A，推进15分钟，观察映射目标、0.5K限速、下发与实际室温的区别。
3. 撤销B或等待期限，观察旧裁决失效；输入26°C后看到不可行提示。房间只有供暖，没有主动制冷。
4. 正常结束保存。现有“同起点规则对照”按钮使用忽略请求的演示规则，属于工程对照，不能作为等需求满足下节电证据。

本次F验收只用既有样例回放，没有为演示补跑物理回合或研究实验。

## 7～10分钟：解释为什么停止

打开[C2报告](../reports/residential_c2/REPORT.md)：464动作已用满，事件覆盖不等于稳态供暖覆盖；6小时温度RMSE约0.082K，但电量绝对偏差2.019kWh超过0.75门。模型未获资格，所以工作台保留规则，未消耗新校准/测试。

再看[交付报告](../DELIVERY.md)与[复现层次](REPRODUCE.md)，区分已复核的回放/门判定、依赖本机档案的完整研究重算，以及尚未完成的真实楼宇/RL/Sim-to-Real。结束时不要把页面停在历史画面却介绍成实时控制。
