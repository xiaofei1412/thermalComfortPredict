## 本次子阶段：带保护激励与动态预测基线

### 目标与验收

1. 补充可追溯的随机块激励，执行动作限幅、限速、温度保护和中止检查，报告未能消除的舒适区间越界。
2. 训练、验证、测试同时按独立回合和时间隔离，预热及历史/未来窗口均不得跨角色。
3. 建立持久性、线性与简单非线性模型，验证15分钟到24小时的自由递归预测，明确未来信息条件。
4. 验证源摘要、模型保存重载、独立重训及防泄漏；保留阶段结果和接口，为 MPC 提供输入，不提前宣称控制收益。

- 仅为已有 `simulation.py` 增加激励分支、任意起始日初始化及保护决策日志，复用原有原生积分、动作对齐、KPI 和 finally 释放逻辑。原规则/内置路径测试继续通过；未修改历史预测资产或重写上一阶段报告。

### 结果、发现与限制

- 全部原生操作温度在18～28°C中止带内，极值21.069～27.406°C；恢复17步、减热282步、限速453步，保护决策可逐步重放。第119日起回合仍有52.942 K·h温度越界；这是供暖控制面对过热的能力边界，不能称为舒适安全保证。
- 完美天气条件下，ExtraTrees在两测试回合的4小时操作温度 RMSE 为 **0.364/0.854°C**，持久性为 **0.648/1.062°C**；24小时分别为 **0.451/2.863°C**，后者差于持久性 **1.436°C**。
- Ridge一步较准但长时无稳定优势，第119日起回合4小时路径中59.22%的耗电预测为负。保留原始负值与计数，不用裁剪掩盖；此耗电输出不能直接用于优化目标。
- 较暖测试回合约66.37%的外温起点、32.44%的操作温度区间末端超出训练回合观察范围；分布变化与退化并存，但未通过因果消融确定全部误差来源。
- 天气冻结条件下，ExtraTrees两回合4小时温度误差为0.527/0.943°C；未来外生量与已执行动作的信息假设必须随指标一起报告。
- 这些结果只覆盖同一已知建筑和确定性天气年；起点窗口重叠，不能当作独立重复实验。Ridge谱半径0.9363并不等于误差有保证，未验证跨建筑泛化或真实迁移。

### 阶段结论与下一步

本子阶段完成了带保护激励、严格切分、多步预测与验证接口，正式证据见 [动态模型报告](../../reports/dynamics/REPORT.md) 和 [实验协议](../experiments/dynamics.md)。整个里程碑1尚未完成。

下一步先处理能耗非负和动作响应验证，再在受支持范围与较短时域内定义误差裕量、回退控制，随后进行 MPC 闭环对照。不能将现有模型直接当作可靠约束模型，也不能删除较暖失败回合来抬高成绩。

## 本次子阶段：灰箱残差、动作响应与短时 MPC

### 目标与验收

1. 尝试正参数热阻—热容灰箱加学习残差，建立结构性非负耗电与受约束动作响应。
2. 用独立FMU成对干预检查动作响应，在时间留出的验证数据上确定经验温度裕量。
3. 跑通2小时预测、15分钟重规划、共同保护及规则回退，与相同条件的带保护规则比较。
4. 重算KPI、重放全部决策、验证模型重载和独立重训，保留负面结果，更新PROJECT.md并同步main。

### 变更与固定决定

- 新增 `configs/mpc.json`、`thermal_comfort/greybox.py`、`thermal_comfort/mpc.py`、验证/报告脚本及14项测试，无新增Python依赖。`simulation.py`只增加可注入控制策略、相同自定义初始化、决策日志和过去区间供热观测，原预测/仿真/动态流程保留。
- 2R2C热网络用正R/C、有界辨识与矩阵指数离散化，包含一个操作温度节点和一个未观测热容节点。Ridge只学习外生量驱动的有界温度残差。执行器模型供热限0～15 kW，功率回归系数与基函数非负，不裁剪旧Ridge的负结果来掩盖问题。
- 只在起始日14/35/56的训练回合拟合。开发期曾共用验证回合选残差/定裕量，正式方案改为前3天65个起点选参，间隔1天，后3天71个起点校准裕量。选中残差权重1；测试回合不用于拟合/调整。
- 第84/90日起分别运行21.5/22/22.5°C三支FMU，前2小时相同22°C预序列，随后保持8小时；模型和配置在干预前冻结。高低档2小时差分方向与非零响应通过后才运行控制。
- 固定2小时预测/15分钟重规划、两步分块、块变化−0.5/0/+0.5 K；最多81计划经边界裁剪去重，选出满足收紧温度约束和支持范围的最低成本计划，仅执行首动作。采用有限枚举，没有引入额外求解器依赖。
- 规则与MPC共用18～23.25°C、0.5 K/步和温度恢复/减热保护。MPC在初始化、支持范围之外、无可行计划或非法预测时回退；18～28°C是中止带，不是舒适或连续时间安全保证。
- 正式模型/干预/控制目录为 `outputs/greybox-mpc/`、`outputs/action-response-final/`、`outputs/mpc/`。开发期的其他模型/干预输出未作为正式工件，完整轨迹和权重不提交Git。

### 发现与修复

- 第一次控制冒烟在JSONL写入时遇到NumPy布尔标志不能序列化；显式转换为Python bool，新增严格JSON日志回归测试。失败目录 `outputs/mpc-smoke/` 保留，之后四支冒烟通过。
- 枚举测试最初假定总有81个不同计划，但靠近动作上界时裁剪会产生重复，实际为80；调整为在不饱和初值验证81，并单独核查边界去重、分块和限速，未改模型来满足错误预期。
- 非负功率模型仍在零供热时保留约0.30 kW基准项；把空载偏差写入报告，不把非负等同于完全物理正确。
- 经验裕量跨工况覆盖不足、暖工况大量回退、耗电下降伴随越界略增均保留，未按控制测试结果继续调参。

### 实际执行与验证

- `python -u -m thermal_comfort.greybox`：正参数RC、执行器、非负功率及残差拟合通过，残差权重0/0.5/1的验证前段目标为0.15334/0.14495/0.13775°C；选择1。独立验证后段的逐步裕量为约0.273～0.742 K。
- `python -u -m thermal_comfort.mpc response --output outputs/action-response-final`：六支各40步（2小时共同预序列＋8小时干预），共240条转移、7,206个原生点。成对初始状态完全一致，2小时高低档温差实际0.650/0.960°C、预测0.655/0.655°C；耗电差实际2.725/4.069 kWh、预测3.732/3.469 kWh。
- `python -u -m thermal_comfort.mpc run --response outputs/action-response-final --days 0.25 --output outputs/mpc-smoke-2`：四支各24步真实FMU冒烟通过。
- `python -u -m thermal_comfort.mpc run --response outputs/action-response-final`：起始日98/119、规则/MPC各7天，四回合共 **2,688条转移、80,644个原生点**；全回合完成并释放testid。
- `python -u -m thermal_comfort.greybox --output outputs/greybox-repeat`、`python scripts/verify_mpc.py --repeat-model outputs/greybox-repeat --repeat-sim outputs/mpc-smoke-2`：模型重载、独立拟合、原始摘要、全部模型指标、选参/裕量重建、全部动作与决策重放、干预门槛重建、初始化/外生一致性、实际动作/限速及原生中止带均通过。重训参数摘要和指标数值精确一致；四支首6小时轨迹精确复现，完整7天未重复。
- 原生能耗、温度越界、成本和排放与API KPI最大绝对差 **5.69e-14**。决策重放容差1e-10，墙钟耗时不参与数值复现。
- `python -m unittest discover -s tests -v`：**51项通过**（原37＋新增14），涵盖物理结构、耗电/单位、即时动作响应、未来状态/供热无泄漏、策略可行性、保护/回退、日志和中止。
- `python scripts/report_mpc.py`：生成紧凑模型/决策证据、首日样例及闭环/动作响应图，已查看两图，单位、图例与曲线正常。

### 结果、边界与后续

| 窗口 | 规则/MPC组合耗电 kWh | 规则/MPC组合温度越界 K·h | MPC接管 |
| --- | ---: | ---: | ---: |
| day98 | 193.314 / 180.002 | 7.915 / 7.966 | 499/672，74.26% |
| day119 | 61.954 / 60.687 | 39.412 / 39.978 | 163/672，24.26% |

组合控制器耗电降低6.89%/2.05%，温度越界增加0.0509/0.5663 K·h，未同时改善两个目标，也未做统计显著性检验。较暖场景主要依赖回退，不能将全部表现归因于MPC。

新灰箱残差模型在旧激励测试轨迹上的2小时温度RMSE为0.422/0.533°C、累计耗电RMSE为0.728/0.664 kWh，功率非负。残差对较冷回合温度误差没有改善。2小时经验裕量覆盖率仅89.36%/85.11%，未达到95%；MPC接管子集的一步覆盖95.79%/100%不能推广到全工况。

本次基线链路已贯通，但温度约束仍有违反，供暖控制不能主动消除过热，人员需求模型尚未接入。完整结论见 [正式报告](../../reports/mpc/REPORT.md) 与 [协议](../experiments/mpc.md)。下一步针对支持范围、回退恢复、空载耗电和天气/传感误差继续验证，不将本次结果称为可靠真实楼宇控制或Sim-to-Real成功。
