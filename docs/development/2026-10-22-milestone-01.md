# 里程碑 1 开发日志

日期：2026-10-22（北京时间）。

## 本次子阶段：数据重建与预测基线

本次范围为监督预测基础；单热区仿真、动态模型、规则控制与 MPC 尚未开始，不能据此将整个里程碑 1 标记完成。

### 目标与验收

1. 不修改历史原始资产，重新核对标签、单位、缺失值与数据来源。
2. 可复现旧清洗产物；构建标签含义正确、来源隔离的主评测和外部气候测试。
3. 运行均值、线性、树模型、旧网络结构、冷热偏好与 PMV 基线，保留指标与模型。
4. 验证随机种子、切分隔离、保存后重载和旧过滤规则影响。
5. 归档紧凑结果，更新总项目文档并同步 GitHub `main`。

### 主要变更

- 新增 `thermal_comfort/`、固定配置 `configs/baseline.json` 与依赖定义 `pyproject.toml`。
- 新增 `data/manifest.json`，固定原始数据 SHA-256、位置式字段映射及来源核查依据。
- 新增回归、分类、物理基线与清洗消融的命令行流程；大型输出保存在 `outputs/`。
- 新增实际数据完整性、标签语义、切分隔离、指标与网络复现测试，以及 CPU CI 工作流。
- 实验说明见 [`../experiments/baseline.md`](../experiments/baseline.md)，来源核查见 [`../experiments/data-provenance.md`](../experiments/data-provenance.md)。

### 数据与协议决定

- 原始表 107,584 行；四输入完整 71,429 行。主评测室温质控沿用上游 `10 < ta < 40°C`，排除 217 条完整输入记录。旧流程复现不应用这项新规则。
- 旧预处理逐值匹配现存 CSV：完整热感觉记录 71,177，温度—标签规则删除 8,763，再删除 1,715 条非整数记录，保留 60,699。
- 主热感觉任务保留 −3～3 及小数标签。冷热偏好映射为 0/1/2，不混用主观舒适度。
- 预先保留 Cfa 外部气候及全部相关来源；同来源其他气候的 206 条记录不进入开发集合。
- 固定来源组切分与种子 33；五个训练种子为 33～37。输入缩放器仅拟合训练集，神经网络仅按验证集选择权重。
- 没有可信建筑 ID，按来源文献分组；缺失来源的 1,655 条原始记录共用一个未知组。来源隔离不等于已证明具体建筑/人员隔离。

### 发现的问题与处理

- 第一轮准备因缺失来源而停止：将缺失来源合并为同一组，不按行生成虚假独立来源，随后隔离测试通过。
- Numba 的依赖约束要求降低继承环境中的 NumPy 版本：项目环境固定 NumPy 2.3.5，并验证 PMV 与 PyTorch 同时可用。
- 继承环境的 `pip check` 发现项目之外的 inscriptis/lxml 版本冲突。未修改全局安装，另建独立 CPU 环境完成干净安装和依赖检查。
- PMV 默认适用范围会排除部分相对风速、动态衣着、蒸汽压和 PMV 超限记录：保留限制与 NaN，另存覆盖率及警告摘要，不填入假定输入或关闭范围检查。
- 上游资料浏览的部分历史下载链接返回 403，改用官方维护仓库固定提交和 Dryad 元数据 API 核查；本地快照准确发行版仍未确定，不虚填版本号。

### 阶段结果与下一步

| 方法 | 来源分组测试 RMSE | Cfa 外部测试 RMSE |
| --- | ---: | ---: |
| 训练均值 | 1.1501 | 1.1736 |
| 线性回归 | 1.0337 | 1.0661 |
| 随机森林（五种子） | 1.1137 ± 0.0012 | 1.1113 ± 0.0008 |
| 旧网络结构（五种子） | 1.0312 ± 0.0175 | 1.0759 ± 0.0075 |

± 是训练种子间标准差，不是跨建筑置信区间。旧网络没有显示相对线性模型的稳定优势，应继续保留简单基线。

冷热偏好随机森林 Macro-F1 为 0.4522 ± 0.0039（测试）和 0.3854 ± 0.0037（外部）；线性分类的部分概率质量指标更好，不能仅按分类 F1 决定控制评分器。

固定种子随机森林在同一主测试集的 RMSE 为 1.1142；仅将测试人群改成旧过滤保留样本，就降至 0.9658。旧过滤训练模型在未过滤测试集反而为 1.2091，在过滤测试集为 0.9356。这说明过滤与评测人群必须分开报告。

PMV 与六输入模型在共同测试子集比较，覆盖主测试 1,464/7,388 行、外部测试 1,782/12,874 行。不能将这些分数与全样本四输入结果直接排名。

本次子阶段完成。下一步为 BOPTEST 单热区环境与规则控制数据采集；先使用明确温度约束，保留偏好模型作为待继续验证的评分器。本次不报告控制节能或真实 Sim-to-Real 成功。

## 本次子阶段：BOPTEST 单热区、规则控制与轨迹采集

### 目标与验收

1. 固定官方单热区案例、服务版本、模型摘要和单位；本机可启动、停止及重建。
2. 两个官方供暖窗口，在相同初始化和控制步长下运行内置控制与固定规则，保存原始响应、原生功率与控制转移。
3. 验证时间和动作对齐；原生积分独立复核官方能耗、温度越界、成本与排放；重启后重复短回合。
4. 保存紧凑结果与复现入口，更新 PROJECT.md 并同步 main。本次不实现动态模型、MPC、RL 或真实迁移。

### 实施与固定决定

- 新增 `infra/boptest.compose.yml`、存储服务源码构建 Dockerfile 及 `scripts/setup_boptest.ps1`。仅映射 localhost:8080，使用独立本地演示账户，未向官方公共服务提交控制实验或发布结果。
- 本机原有 WSL Ubuntu-24.04，无 Docker；在 WSL 内安装 Docker Engine 29.1.3 / Compose 2.40.3。BOPTEST sparse checkout 位于被忽略的 `outputs/boptest-v0.9.0`，固定 v0.9.0 提交及 `wrapped.fmu` SHA-256。原有预测数据与 legacy 代码未修改。
- 官方 GHCR worker/web 固定镜像摘要；Redis 同样固定摘要。上传工具沿用上游 Dockerfile，辅助构建的系统包及 HTTP 依赖未完全锁定，详见运行协议。
- 新增 `thermal_comfort/simulation.py` 和 `configs/simulation.json`，使用标准库 HTTP 客户端；无新增 Python 依赖。四回合分别重新选取模型、官方预热 7 天、评测 14 天，每步 900 s。
- 规则在正式运行前固定为有人下界 +0.5 K、无人下界 +3 K，仅覆盖 `oveTSet_u`；不利用未来气象/占用，也不使用未校准的人员模型。没有按正式结果继续调参。
- 同时保存约 30 s 原生网格与 15 分钟转移。能耗积分三项电功率；温度指标是操作温度越界 K·h，不混称主观舒适评分。
- 新增 `scripts/verify_simulation.py`、`scripts/report_simulation.py`、10 项仿真离线测试和协议文档；原工作流自动发现新测试。紧凑证据见 `reports/simulation/`，完整正式工件约 24.2 MB，留在 `outputs/simulation/`。

### 发现的问题与处理

- Docker Hub 的旧 `nrel/boptest-worker:v0.9.0` 不存在；按官方发布脚本改用 `ghcr.io/ibpsa/boptest-*` 并固定摘要。
- 上游 Compose 依赖的 MinIO Docker Hub/Quay 镜像无法拉取，官方二进制归档返回 410；改从 MinIO/mc 官方 GitHub 固定提交下载源码，核对归档 SHA-256，使用固定 Go 镜像构建。保留 AGPL 来源与第三方许可说明，没有采用未知镜像替代。
- WSL 路径转换最初因 Windows 反斜杠失败；先转正斜杠再调用 wslpath，后续部署、重建和重复启动通过。
- 首次真实 API 冒烟发现空 POST JSON 请求体触发上游解析错误，停止接口返回纯文本而非 JSON；修正客户端并添加回归测试。失败目录 `outputs/simulation-smoke*` 保留，正式结果不包含失败数据。
- 保存后核验最初因 embedded 的空请求值 `None/NaN` 表示、首日全零列的整数/浮点推断差异停止；核验明确统一数值表示并忽略读入类型推断，仍要求重复轨迹数值精确相等，不放宽数值容差掩盖差异。
- 提交检查发现 Windows 生成的报告 CSV 使用 CRLF，被 Git 视为行末空白；在报告生成入口显式指定 LF 并重新生成，仅改变文本换行，指标与原始实验工件不变。
