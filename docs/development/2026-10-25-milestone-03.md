# 里程碑 3 开发日志

日期：2026-10-25（北京时间）。本子阶段只评估冻结控制器的仿真泛化，不包含目标域重训、少样本校准或真实楼宇迁移。

## 目标与固定验收

1. 冻结`d156645`的源码、有效配置、正式模型和经验裕量，目标域训练数据为零，原测试只作为回归，不再用于调参。
2. 原住宅/布鲁塞尔、同住宅/丹佛TMY、官方办公室/丹佛TMY三个域；固定day210/259/343、三种预报、两控制器，共54个7天回合。评测/预热窗口与旧训练、验证、正式测试隔离。
3. 成对报告电耗、燃气、总终端能量、冷热温度越界分项/时长/最大偏差，多步预测误差、固定裕量覆盖与回退比例。零电耗和失败回合保留，不能靠平均值、冷热抵消或能源转移声称成功。
4. 完成冻结摘要核验、原生KPI独立积分、全部决策重放、共同初始化/规则天气不变性，以及各支首6小时独立重复；不声称重复整个7天。

## 实施

- 新增`configs/generalization.json`、`thermal_comfort/generalization.py`与[预先固定协议](../experiments/generalization.md)。旧控制器和配置未修改，所有正式运行逐回合核验冻结SHA。
- 住宅天气迁移只替换FMU的实际天气资源、预报CSV及案例名称；官方原FMU、编译二进制和模型描述不变。办公室使用固定BOPTEST 0.9.0官方`bestest_air`，48 m²，空气温度与住宅操作温度分开报告。
- 接口映射不学习目标数据。办公室供热取官方燃气读数×0.9，内置冷却保持，原热泵电功率目标映射故意不适配，以揭示零样本迁移限制；不能解释为办公室总能源成本优化。
- 统一6天内置预热＋1天22°C共同预序列，正式评测前重置策略状态。预序列单独保存，不计评测电量；官方KPI包含该一天，所以另外对包含预序列的完整时间段积分核验。
- 冻结后新增审计与归档脚本，检查真实接口、实际气象位置/太阳几何、能源载体、逐日指标、预测和回退，不改变控制行为。

## 阶段结果

| 测试域 | 全部门槛通过 | 结论 |
| --- | ---: | --- |
| 原住宅/布鲁塞尔新日期 | 6/9 | 六个非零电耗组节电2.53%～5.32%，越界不增；夏季三组零电耗仍过热 |
| 原住宅/丹佛TMY | 0/9 | 六组零电耗仍过热；冬季三组约−0.0250%～+0.2233%节电，越界均微增 |
| 官方办公室/丹佛TMY | 1/9 | 唯一通过组只省0.000570%，约0.000100 kWh，不算实质迁移收益 |

固定27组总计7组通过，不推断独立随机成功率。办公室day259完美预报电耗50.114→50.002 kWh、燃气5.340→4.759 kWh，但越界3.463→3.474 K·h；偏暖预报总越界略降，却因最大过热增加约0.000017 K未通过，保持原数值门槛且不夸大微差的工程意义。

丹佛住宅day210规则/MPC均零电耗、约812.018 K·h过热；day259约228.432 K·h。住宅没有制冷，本轮不能将零供暖过热解释为所有控制手段的物理下界。

本轮没有使用新目标轨迹选模型、改裕量或调控制参数，也没有更改旧源域控制代码。参数冻结、在线因果观测器更新保留；目标供热观测仍依赖FMU，不是已完成真实Sim-to-Real。

规则轨迹完美API视图的6小时温度RMSE：源住宅0.103～0.364°C，新气候住宅0.639～1.791°C，办公室空气温度1.412～3.770°C。端点裕量覆盖分别96.18%～100%、36.94%～84.08%、26.75%～55.41%；办公室夏季/过渡季差于持久性。冬季完美预报丹佛住宅/办公室回退分别88.40%/99.10%，不能将近乎规则的表现当作模型迁移可靠性证据。
