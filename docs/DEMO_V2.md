# 五到十分钟：重放两代控制，而非启动RL接管

使用已验收Python3.14，在解压源码目录运行；本页只有标准库，不需Torch、Docker、权重或历史CSV：

```powershell
py -3.14 -m scripts.verify_v2_delivery
py -3.14 -m scripts.serve_v2_demo --port 8772
```

打开终端URL。8772被占用时选择另一个端口，不覆盖已有服务。页头必须显示“ARCHIVE · 已封存开发轨迹”，不存在新建仿真、发送动作或人员请求入口；播放速度只影响画面。

1. 保持默认冬季084/SAC/种子11，前2小时三策略状态相同。播放或拖动时间，比较操作温度、实际供暖设定、此刻电功率与累计电量；完整7天指标独立显示。原SAC省电却新增过冷，不能只看电量。
2. 选择规则残差SAC/种子37，点“跳到首次冷越界时段”。查看库残差、当前轨迹的规则锚和实际下发；该时段可能发生区间内部越界，帧末温度已恢复，提示会明确说明。其冬季过冷5.703K·h，不能因为动作有规则锚就认为舒适有保证。
3. 切到暖168/PPO/种子23和整周终点，核对49.31kWh与16.939K·h过热；规则/MPC约8.77/6.58kWh。再看TD3/37可见局部暖窗口通过，但其冬季失败，不能选最好窗口代表算法。
4. 切189，看到电量0与严重累计过热；供暖设定下降不能提供主动制冷。此组不展示节电百分比。选minimum_heat时种子控件禁用，避免伪造该规则的随机重复。
5. 展开“能说明什么”，说明日程越界不是真实热舒适投票、帧图不是建筑几何孪生、三种子不是三种独立天气。最后看[交付报告](../DELIVERY_V2.md)、[策略边界](V2_POLICY_CARD.md)和[复现层次](REPRODUCE_V2.md)。

全部3窗口、4种RL方法×3种子及3个参照共45条轨迹均在包内；默认第一个登记种子不是最好种子。曲线和房间显示15分钟边界帧，展示数值保留6位小数；门判定仍使用原30秒数据的全精度封存指标。

第一版亲自操控房间、人员请求/撤销/过期与冲突裁决仍按[原演示](DEMO.md)使用；它与本页研究任务分开。V2-7不为演示补跑新的仿真回合，也不把回放或原规则工作台称为在线RL部署。
