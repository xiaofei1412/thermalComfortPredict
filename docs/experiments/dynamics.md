# 带保护激励与动态预测基线协议

本阶段在固定 BOPTEST 0.9.0 单热区热泵模型上补充激励，建立可递归调用的状态与耗电预测基线。未实现 MPC，未把预测误差表述为控制收益。原模型、部署、操作温度及功率单位沿用 [仿真协议](simulation.md)。

## 采集与保护

固定配置为 `configs/dynamics.json`。各回合重新选取 FMU，以内置控制预热 7 天，再采集 7 天；900 s 一步，原生约 30 s。仅覆盖温度设定，底层热泵 PI、风机和水泵控制保持原模型逻辑。

- 计划激励为 22°C + 从 `[-0.75,-0.375,0,0.375,0.75] K` 有放回抽样的偏移，每块保持 8 步（2 h）；独立种子固定于各回合。保护干预不改变未来计划激励的随机序列。
- 请求设定限制在 18～24°C，同时遵守 API 动作范围；包括首步在内，相邻请求相对上一次实际设定的变化不超过 0.5 K/步。
- 当前操作温度低于 `max(舒适下界+0.2 K,19°C)` 时，提高目标至 24°C；高于 `min(舒适上界−0.2 K,27°C)` 时，目标降至 18°C。保护目标也受相同动作/变化率限制，因此不是瞬时强制恢复。
- 每次决策前、advance 返回后检查 18～28°C 中止带，非有限值或超带直接中止，保留逐步日志；完整回合再核对原生采样的温度极值。步间短暂越界不能靠 15 分钟反馈提前阻止，只有原生采样事后核查。
- “安全激励”在这里指**带边界、限速与温度监控的仿真采集**，不是对舒适区间或连续时间状态的形式化安全保证。过热时此案例只有减热能力，没有受本流程控制的主动制冷。越界、干预和中止均必须报告。

每步 JSONL 额外保存计划设定、保护模式、目标、前次/本次请求及限速标志；按种子重放可验证动作和保护决策。完整工件仍使用原有 native/exogenous/transitions/API KPI 格式，摘要记录各回合配置与哈希。

## 状态、输入与目标

状态为 `[操作温度°C, 回水温度°C, 供水温度°C, 上一区间耗电kWh]`，前三项在决策时刻测量，耗电由前一已完成区间的三项原生电功率积分得到。首个状态的上一周期耗电未知，置为 NaN 并排除所有涉及它的窗口，不用假定初值补齐。

输入特征为按时间从旧到新排列的 `lag × 4` 状态历史、`lag−1` 个历史动作加本次设定温度，以及本次区间起点的 `[室外温度°C,水平总太阳辐射W/m²,占用人数,日内时刻sin,日内时刻cos]`。当前动作属于 `[t_k,t_{k+1}]`；目标前三项为 `state[k+1]−state[k]`，耗电目标为本区间 `E_k` 的绝对值。当前区间的实际耗电、未来状态、水路输出均不进入本次输入。

只训练训练回合，StandardScaler 仅拟合训练特征，不对验证或测试重新拟合。Ridge 和 ExtraTrees 都预测四个目标，递归时将前三个温度增量加到本次预测状态，耗电使用新预测的区间值。没有温度或能耗截断；非物理负耗电要显式计数，不能靠裁剪掩盖。

## 模型与选择

- 持久性：各预测步保持起点的温度和上一周期耗电不变。
- 线性 ARX：StandardScaler + Ridge，lag 为 4/8/16、alpha 为 0.1/10，共 6 个候选。
- 非线性 NARX：128 棵 ExtraTrees，lag=8、最大深度18、叶最少样本2/8，共 2 个候选；固定种子33、单线程。
- 每个模型族按验证回合的 1、4、8 h 末端操作温度 RMSE 均值选择；不是按测试最优选择，也没有将验证数据加入重训。选择完成后写入 selection.json 并保存模型，再计算测试结果。耗电和水路误差另报，没有把它们包含进选参目标。

初次开发运行后补充了水路误差与分布覆盖率诊断；候选、训练数据、选择指标未随测试表现改变。正式运行与独立重训结果保存在独立目录。

## 多步评测与未来信息边界

预测时域固定为 1/4/16/32/96 步，即 15 min、1/4/8/24 h。对验证与两个测试回合，在第16步之后每4步取一个起点，并保证最长96步仍在同回合内，各回合 **141 个相同起点**用于全部模型、全部时域。短时域也使用这组起点，因此没有涵盖所有可能的一步预测样本。

起点提供一次测量历史，之后**自由递归**，不使用任何后续真实状态做 teacher forcing。`rollout()` 接口根本不接受未来状态。温度 RMSE/MAE/p95/max 是各时域**末端**误差；耗电误差是该时域内预测与真实区间耗电的累计差。水路温度误差和负耗电比例同时记录。

两种未来信息条件分别报告：

1. `perfect`：已执行的未来动作、确定性完美天气、占用和日程时钟。对应理想外生预测条件。
2. `hold`：未来室外温度与太阳辐射冻结在起点值；动作、占用、日程时钟相同。该假设可能比真实天气预报更差，不代表所有实际预报误差分布。

未来动作来自实际闭环日志，其中部分受到未来实测状态的保护干预影响；这些是**给定已执行动作序列的条件预测误差**。没有泄漏未来状态到模型特征，但仍不等于模型能对任意候选动作做准确反事实预测。天气/动作已知的理想评测不能直接当成真实 MPC 闭环结果。

同回合滚动窗口彼此重叠、误差相关；141 起点不是141个独立实验，不据此计算跨建筑置信区间或显著性。两个测试回合分别报告，不以一个总体均值掩盖较暖回合的退化。

## 运行与验证

Python 沿用现有依赖环境，无新增包。先按仿真协议启动本地服务，再在项目根目录执行（目录必须不存在）：

```powershell
.\.venv-cpu\Scripts\python.exe -m thermal_comfort.excitation --days 0.25 --output outputs/excitation-smoke
.\.venv-cpu\Scripts\python.exe -u -m thermal_comfort.excitation
.\.venv-cpu\Scripts\python.exe scripts/verify_simulation.py --output outputs/excitation --repeat outputs/excitation-smoke
.\.venv-cpu\Scripts\python.exe -u -m thermal_comfort.dynamics
.\.venv-cpu\Scripts\python.exe -u -m thermal_comfort.dynamics --output outputs/dynamics-repeat
.\.venv-cpu\Scripts\python.exe scripts/verify_dynamics.py --repeat outputs/dynamics-repeat
.\.venv-cpu\Scripts\python.exe scripts/report_dynamics.py
.\.venv-cpu\Scripts\python.exe -m unittest discover -s tests -v
```

采集默认输出 `outputs/excitation/`，正式模型默认 `outputs/dynamics-baseline/`，重复模型 `outputs/dynamics-repeat/`；模型、完整逐起点误差和完整轨迹不提交 Git。`reports/dynamics/` 保留紧凑证据和图。

验证包括：源文件摘要、带预热的时间/角色隔离、动作及保护重放、原生积分与官方 KPI、同种子六小时轨迹前缀复现、模型保存重载、重新计算全部滚动指标、独立重训数值复现，以及覆盖防泄漏和安全保护的离线测试。只重复了六小时 FMU 前缀，不声称完整7天仿真逐点重复验证。joblib 文件只应加载本机可信生成物。

## 为 MPC 提供的接口与边界

`models.joblib` 中保存 `ridge`、`extra_trees`、`persistence` 三个模型。`thermal_comfort.dynamics.rollout(model, history, past_actions, future_actions, future_exog)` 返回 `[batch,horizon,4]`：预测下一时刻三个温度及本次区间耗电。参数形状见函数文档；只需要起点历史和候选控制/外生序列，后续 MPC 可以直接调用。供回水温度必须真实可测，不能在新建筑上假定可用。

当前报告已暴露负耗电、较暖天气外推和长时漂移，**不能把现有模型直接当作无保护 MPC 的可靠约束模型**。下一步应先定义受支持动作与预测时域、检查能耗非负/动作响应、设置误差裕量和回退控制，再做短时域仿真 MPC 对照；对优化器提出的新动作还需独立 FMU 干预验证。线性历史状态矩阵的谱半径仅是固定外部输入下的递归诊断，小于1也不保证带外生输入/模型偏差的预测正确。
