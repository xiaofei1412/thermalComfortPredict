# 原生30秒末端辨识、联合多步训练与开发能力门

本轮以`e537267`为起点，所有旧源码、模型、校准、测试保持冻结。办公室仍为48 m² bestest_air、空气温度；热效率0.9、冷却COP3、原生30秒、供暖设定值决策900秒。原生采样不等于30秒改变供暖动作，不改变原动作范围、限速、18～35°C中止带。规则控制是主要可部署基线。

## 数据和先后顺序

复用上一轮**开发数据**的原生信号：train=丹佛day24/94/124/328各3天；development excitation=day62/150各3天。旧开发角色不变，旧校准和正式测试不读入拟合、选模或能力门。另在两个开发日期采集各3天guarded_rule轨迹，作为主要分布检验；已有两档20.5/23.25°C、各日期半天的开发干预只作动作响应检验。回合连同7天初始化隔离，角色跨季节交错，不能称全年未来先后切分。

先固定本协议、配置和门槛，再读取本轮预测结果。保留原生辨识候选和相同结构的联合多步候选，不为过门反复调整阈值/损失/季节标签。允许比较这两个预定候选；部署资格要求同一个候选所有开发能力门通过，不能拼接季节最优成绩。没有候选通过则固定规则控制、停止校准/新场景流程，保留负结果；数据完整性/单元测试通过不算能力门通过。

条件性下一阶段：全部开发门通过，独立重训与审计通过后写开发锁，才采集新的丹佛day51/110/276各1天校准。其7天初始化窗口避开所有历史丹佛办公室角色。校准之前不创建校准数据目录。新场景须在锁前具体确定并验证未使用身份，不能把旧布鲁塞尔办公室测试再当新场景。若开发失败，此计划不执行，也不声称完成校准或盲测。

## 最小模型与训练

使用30秒离散2R2C空气/蓄热状态，显式模拟两个PI控制记忆、冷却迟滞和风量一阶动态，联合输出温度、燃气功率、冷却电功率、风机电功率。末端先验来自固定BOPTEST源`Thermostat_T.mo`、`ControlToTemperature.mo`和`FanCoilUnit_T.mo`：PI比例0.1、120秒积分时间初值，风量0.55kg/s，供暖21～40°C、冷却24～12°C、冷却切换迟滞−1/0K，风机不向空气加热。这是已知仿真结构上的灰箱辨识，不声称从数据恢复真实控制器/墙体温度。动态参数和非负风机多项式、冷热功率比例由训练数据辨识。

每个预测起点只用过去温度/功率/风量重建PI记忆，蓄热状态由历史区间热量观测更新；低风量时使用因果PI推进，不能按未来功率初始化。归一风量容许1e-6的FMU数值误差后截到0～1，功率只容许1e-9kW负尾差后截零，原始CSV不改。30秒区间功率按端点梯形积分；预测也保持这一约定，不将末端功率当平均量。已知未来记录动作与公开预报作为条件输入；自由滚动不注入未来实测温度、功率、风量或PI状态。

先用训练样本的30秒温度及三类功率联合辨识，再从该结果优化同一模型的30秒/5分钟/15分钟/1小时/6小时自由滚动温度、端点功率与累计能源损失；功率按1/0.5/0.1kW固定归一，累计能源除以预测时长后同样归一，各时长等权。全部热网络、末端和功率参数同时更新，禁止只优化温度再单独补能源头。确定性有界最小二乘，两候选固定预算。训练起点每2小时；验证起点每小时，前4小时只用于状态预热；重叠窗口不称独立样本。

## 预设能力门

冷季day62和暖季day150分别在规则/激励轨迹检验，不能用平均分掩盖一个季节或一种能源失败。能源始终分燃气、制冷电、风机电，不合并抵消。

- 每条轨迹至少20个6小时起点。1小时/6小时温度RMSE≤0.5/1.0K，且比冻结15分钟静态模型恶化≤0.05K。
- 每季、每能源的1小时/6小时累计能量RMSE≤`max(该能源绝对下限,0.2×真实累计量RMS)`；绝对下限燃气/制冷/风机=0.05/0.05/0.005kWh。还须不比原模型恶化超过0.01/0.01/0.001kWh。
- 5分钟/15分钟原生端点功率RMSE≤`max(绝对下限,0.3×实测功率RMS)`，下限0.1/0.05/0.01kW。此项原15分钟模型无合法5分钟端点输出，不伪造插值比较。
- 每个季节/能源至少10个活动6小时起点（真实窗口平均功率>0.1/0.05/0.005kW），否则标记证据不足、该格不授予能力；低耗电不会因相对误差分母接近零而产生虚假百分比。
- 同日配对干预的首小时燃气和温度响应方向须正确；6小时燃气响应差的误差≤`max(0.05kWh,真实差绝对值×0.5)`。没有激励的分支报告证据不足，不算成功。

能力门是经验开发资格，不是安全证书。任何一个温度或能源格失败/证据不足，全局升级门不通过；禁止据校准或测试结果重定门槛。训练/数据完整性审计与能力判断分别报告。

完整产物在`outputs/native-*`；紧凑报告在`reports/native_terminal`。若通过，后续锁定还必须绑定控制策略、校准算法与新场景身份，再开展独立校准和控制对照；本轮不会把预测合格直接写为节能/Sim-to-Real成功。
