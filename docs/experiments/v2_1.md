# V2-1：接口工程验收（运行前登记）

父协议为 configs/v2_0.json 与 reports/v2_0/lock.json，不修改父锁。只允许 train014：day14 起、7天预热、7天有限任务；禁止训练、开发/留出初始化和读取。新副本 thermal-rl-v2:8082 使用原 FMU，不占用工作台引擎。

运行顺序与硬上限见 configs/v2_1.json：旧入口冻结规则672步、Gym接口相同规则672步、8步共同前缀＋16步动作探针，共3次初始化、1368次advance尝试（包含前缀）、90分钟；失败尝试同样消耗预算，不重发未知结果的advance。上限耗尽即停止，不追加回合。工程修复保留失败证据；需要新运行预算时须先修订并说明。

规则参照用原 simulation.run_episode 与原 SolarController。旧入口预取整段外生量仅用于此 train014 参照，绝不传给RL接口；新接口每次只查询当前至+43200秒，30秒原生日程用于积分，900秒49点提供给actor。二者完整轨迹逐步核对，不能仅比较总量。

动作是 float32 单元素 [-1,1]，相对前次实际设定增加±0.5K，再投影至18～23.25°C；非法形状、NaN、越界输入拒绝且不advance。所有真实下发与FMU覆盖值、限速逐步核对。前8步由冻结规则执行，reset返回其后观测；启动段完整积分，但没有actor转移。

观测为Dict：16行可见历史（操作温度°C、实际/上次设定°C、瞬时供热kW/电功率kW、最近完成区间平均供热kW、日钟sin/cos、剩余控制步数）；历史左零填充并附有效mask，不读预热隐藏轨迹。预报49×7，字段顺序与父协议一致，温度预报保持K、其余原单位；时间从当前严格递增900秒至12小时，不含未来状态/耗电。首行平均热量无完成区间时为0，mask区分有效历史。无统计拟合/归一化。

Gymnasium reset返回(obs,info)，step返回(obs,reward,terminated,truncated,info)。有限任务到第672步（actor第664步）terminated；操作温度出[18,35]°C为失败终止、不可参加节电比较。外部短探针上限为truncated，保留最后真实观测。网络/原生数据错误抛异常、使回合失效，释放worker，不伪造正常转移，也不重试。结束后再step须拒绝。工程reward仅为负区间kWh；学习奖励、折扣、越界/失败惩罚与预算尚未授权，禁止据此训练。

每步取含首尾31点的30秒原生温度、功率及日程，梯形积分电量和冷热K·h、原生越界采样时长/最大偏差；区间边界的动作属于前一动作，之后30点须匹配本次下发。能量奖励仅actor段，正式总分含前缀；原生积分与官方ener/tdis/cost/emis核对。短探针/失败回合不得作为7天优胜结果。

门：Gymnasium官方checker（假引擎，不额外消耗FMU）、边界/动作/错误/结束语义单测、真实两入口逐步等价与原生KPI一致、动作探针限幅限速无违反、完整成本账本。动作/温度逐样本绝对差≤1e-6K、电量总差≤1e-6kWh（float32动作传输容差），官方KPI沿用父流程1e-6绝对/相对容差。记录初始化/预热/前缀/step耗时与尾部时延、仿真比、全回合耗时。吞吐仅用于建议后续预算；V2-2负荷/动作响应门和学习设置锁未完成时，不授予训练资格。

官方依据：[Gymnasium Env](https://gymnasium.farama.org/api/env/) 与[结束/截断](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)。[BOPTEST-Gym源码](https://github.com/ibpsa/project1-boptest-gym/blob/master/boptestGymEnv.py)采用同REST/Gymnasium方向，但默认动作oveHeaPumY_u不同，且依赖SB3；本轮使用小型自有适配器以保留冻结oveTSet_u、共同启动段和30秒审计，不声称已兼容其全部包装器。未安装SB3或训练库。
