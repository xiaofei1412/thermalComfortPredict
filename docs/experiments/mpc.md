# 灰箱残差模型与短时域 MPC 协议

本阶段完成正参数热网络、非负耗电模型、独立 FMU 动作干预、经验温度裕量和带回退的短时 MPC 对照。使用固定 BOPTEST 0.9.0 单热区供暖案例，仍是仿真研究；不声明真实楼宇数字孪生、形式化安全或 Sim-to-Real 成功。原数据来源、单位和部署见 [仿真](simulation.md) 与 [动态模型](dynamics.md) 协议。

## 数据和角色

- 复用 `outputs/excitation/`，SHA-256、完整步数和时间/回合隔离仍由原加载器核对。三个训练回合起始日14/35/56，验证回合77，测试回合98/119，各7天。
- 每个900 s区间的供热量由原生 `reaQFloHea_y` 梯形积分得到平均kW。仅训练参数辨识使用当前区间的真实供热；自由预测使用执行器模型预测的供热。实时控制更新只读取**已完成区间**的供热积分与操作温度。
- RC、执行器、耗电和残差回归仅拟合三个训练回合。验证回合前3天选残差权重（65个起点，4小时窗口不越过该段）；空出1天后，用后3天的71个起点估计2小时误差裕量。当前隐状态允许使用截至起点的过去观测，不能使用未来状态或未来供热真值。
- 第84/90日起的独立FMU干预仅用于动作响应检查，不用于重拟合或选择参数；它们是校准情境，不是测试成绩。第98/119日起各7天为固定控制对照窗口，观察结果后未调参。
- 所有时间指模型年内天数，评测区间左闭右开。每个FMU独立内置控制预热7天；干预校准窗口的预热可与验证时段重叠，因为它不承担独立泛化测试。

## 2R2C 灰箱与残差

用操作温度 `Tz` 作为可测热节点、`Tm` 作为隐含热容节点，构建本项目的简化模型：

```text
Cz·dTz/dt = (Tout−Tz)/Rza + (Tm−Tz)/Rzm + As·GHI/1000 + qocc·N
Cm·dTm/dt = (Tz−Tm)/Rzm + Q
```

时间单位h，R单位K/kW，C单位kWh/K，Q单位kW，GHI单位W/m²，As单位m²，qocc单位kW/人。6个参数使用对数参数化和有界最小二乘，保持正值。供热注入隐含热容节点，代表地板供暖等蓄热惯性的低阶近似；该节点未经真实温度测量确认，不能当作真实楼板温度。

使用矩阵指数做0.25 h精确零阶保持离散化。辨识损失来自训练回合的15分钟、1/2/4小时滚动操作温度误差，辨识时未来供热可作为已知训练激励；正式预测不允许使用该真值。参数初值和边界写在代码中，未按测试误差改变。

隐状态初值为 `Tm=Tz+Rzm·Qprevious`；每步以实际操作温度替换预测Tz，并将测量残差的0.2倍加到预测Tm。它是因果启发式观测器，不是卡尔曼滤波器或有证明的状态估计误差界。

学习残差为 StandardScaler + Ridge(alpha=10)，输入仅为当前外温、辐射、占用及日内sin/cos，预测RC一步温度残差；不直接读取候选动作或未来观测。残差幅度限制为训练残差绝对值95%分位数，权重候选0/0.5/1只在验证前段选择。残差只修正Tz，保留纯RC消融。R、C等拟合值受状态近似和可识别性限制，不能解释为实测建筑物性。

## 执行器和结构性非负耗电

令 `e=u−Tz`，使用训练数据拟合：

```text
Qk = clip(a·Qprevious + b·e + c·(e−eprevious) + d·(Tz−Tout) + f, 0, 15kW)
Ek = 0.25h · [p0 + p1·Qk + p2·Qk·max(20−Tout,0)/20]
```

约束0≤a≤1，b/c/d≥0，f有界；p0/p1/p2由非负最小二乘得到。即时提高设定温度不会降低预测Q，功率基函数和系数均非负，因此**耗电由结构保证非负**，不是将旧Ridge负输出事后裁剪。

15 kW是建模上限，不是已证明的真实设备安全上限。非负不代表无偏：拟合的p0约0.30 kW，零预测供热时也有基准耗电，存在空载偏差。当前模型没有证明任意动作序列的长期单调性、热力学一致性或预测精度。

本模型不再预测供回水温度，依赖操作温度与已完成区间供热观测。与上一阶段模型的传感器输入不同，离线误差只作参考，不能把所有差异归因于算法结构；真实应用需确认供热观测或估计器可用。

## 独立动作响应检查

在第84/90日起，三支FMU分别独立初始化，先共同执行2小时22°C预序列，再保持21.5/22/22.5°C共8小时。核对干预起点的全部返回状态精确一致。分支使用相同动作边界、变化率与18～28°C中止带；为保持干预清晰，不用日程规则改写中途设定。

比较高低档在15分钟、1/2/4/8小时的温度差和累计耗电差，以及各分支的绝对预测误差。控制启动门槛仅要求2小时高低档差方向一致（实际温差允许−0.05 K、耗电差允许−0.1 kWh数值容差，模型差需≥−1e-8），且至少一个情境实际耗电差>0.5 kWh。门槛文件绑定模型与配置摘要。这个检查不构成幅度误差界，也没有验证全部候选控制序列。

## 误差裕量和控制器

裕量为时间留出的验证后段自由预测的逐时域绝对温度误差95%分位数，加人为0.1 K附加量；后者不是实测传感器误差标定。共8个裕量，从约0.273 K增至0.742 K。窗口重叠且存在分布变化，这不是95%安全概率保证；测试覆盖率必须单独报告。

MPC每15分钟重规划，预测8步（2小时），每2步一块，块间设定变化候选为−0.5/0/+0.5 K。枚举3⁴=81个计划，边界裁剪后去重；在候选中选择成本最低的可行计划，只执行第一个动作。后续周期重新规划，因此实际动作仍可每15分钟变化。这是有限控制集的枚举MPC，不是连续动作空间的全局最优解。

计划需满足18～23.25°C、0.5 K/步、每个未来**端点**的官方舒适下界+裕量及上界−裕量；并限制预测操作温度在训练观察范围±0.5 K。目标为预测电费加 `0.05 EUR/K² × ΣΔu²`。只在收紧温度约束可行的候选中比较电费，不通过温度松弛变量购买违反量。

两控制器共用当前温度保护：低于 `max(当前舒适下界+0.2 K,19°C)` 目标升到23.25°C；高于 `min(当前舒适上界−0.2 K,27°C)` 目标降到18°C，仍受同样限速。18～28°C为中止带，advance前后检查，原生采样事后再核对；这不是连续时间安全证明。

带保护规则基线：有人时设为下界+0.5 K，无人时下界+3 K，叠加相同动作边界、限速和上述保护。MPC也执行相同保护，并在以下情况使用该规则回退：

- 开始8步用于共同规则控制和观测器初始化；两支FMU的这段实际状态/动作需一致。
- 当前温度或未来2小时天气超出训练支持范围。温度/外温/辐射容许训练范围外扩0.5 K/1 K/100 W/m²。
- 没有满足裕量和支持范围的候选计划。
- 预测非有限或出现不合法耗电。

比较对象是**MPC与回退组成的完整控制器**，逐步报告MPC接管与回退原因。相同初始化、预热、动作界限、底层PI、占用、电价和确定性完美天气；两者可访问相同预测，规则实际只用当前值，MPC使用未来2小时，因此比较包含未来信息利用差异，未隔离优化器的单独贡献。未测试预报噪声、传感器噪声或真实通信延迟。

## 运行与验证

沿用既有Python依赖、WSL/Docker和固定FMU，无新增包。在项目根目录执行，输出目录必须不存在：

```powershell
.\.venv-cpu\Scripts\python.exe -u -m thermal_comfort.greybox
.\.venv-cpu\Scripts\python.exe -u -m thermal_comfort.mpc response --output outputs/action-response-final
.\.venv-cpu\Scripts\python.exe -u -m thermal_comfort.mpc run --response outputs/action-response-final --days 0.25 --output outputs/mpc-smoke-2
.\.venv-cpu\Scripts\python.exe -u -m thermal_comfort.mpc run --response outputs/action-response-final
.\.venv-cpu\Scripts\python.exe -u -m thermal_comfort.greybox --output outputs/greybox-repeat
.\.venv-cpu\Scripts\python.exe scripts/verify_mpc.py --repeat-model outputs/greybox-repeat --repeat-sim outputs/mpc-smoke-2
.\.venv-cpu\Scripts\python.exe scripts/report_mpc.py
.\.venv-cpu\Scripts\python.exe -m unittest discover -s tests -v
```

正式模型、独立重训、干预、控制输出分别为 `outputs/greybox-mpc/`、`outputs/greybox-repeat/`、`outputs/action-response-final/`、`outputs/mpc/`。开发期 `outputs/greybox/`、`outputs/action-response*` 其他目录和失败的 `outputs/mpc-smoke/` 不作为正式证据。CLI默认干预输出名为 `outputs/action-response-mpc/`；上面显式命名正式目录，供报告/验证脚本读取。

验证包括训练/选参/裕量角色、非负与热网络稳定性、模型重载、独立重训、原生KPI积分、所有控制决策离线重放、成对干预起点、相同外生数据、实际动作/变化率、原生温度中止带及四支首6小时轨迹复现。决策耗时只计算策略调用，不含HTTP、测量获取和仿真时间。完整7天仿真没有重复运行。

详细实测结果和失败边界见 [报告](../../reports/mpc/REPORT.md)。下一步应针对工况变化、回退导致的舒适恢复、空载能耗偏差和天气误差做验证，不以本次小幅耗电差证明普遍优势。
