# C2：冻结事件、住宅补采与开发停止协议

2026-10-27，在新数据采集和查看标签前固定；继承[C1协议](residential_c.md)全部数据角色、门槛和预算，原配置/旧源码不改。事件表见[residential_c2_events.json](../../configs/residential_c2_events.json)。本轮只准train day224、development day287各192步，以及day287两支40步响应，最多464次advance（失败/超时调用也占预算）。禁止calibration day300、test day329/357的初始化、采集和读取。

## 事件与动作

训练与开发均从00:00起，预热7天，使用同一个6小时循环、共8次，不因天气或结果改变。按小时顺序：A区间22.5～23.25、A不可行26°C并显式按18°C基准、到期无需求回基准18°C、A更暖/B更凉冲突并显式选A、B过期且有效A替换为保持22.5°C、撤销A回18°C。相对请求锚点、期限及基准逐项见事件表；这些是预先登记的虚拟操作者行为，不是自动识别的真实人员需求。

提交只发生在列明的循环边界，期限按900秒绝对仿真时间到期，不逐步续期。过期先于同刻新提交；每次变更递增版本，裁决仅用于该版本。冲突/不可行首次提交先验证未裁决被拒绝且没有advance，再按脚本显式裁决；拒绝记录不增加仿真时长，也不被记作零能耗运行时间。记录每次提交/替换/撤销/到期、拒绝、裁决、快照、映射目标、限速下发和原生响应。

响应两支均在day287独立初始化，前16步同21°C、后24步分别向18/23.25°C限速。它们是预注册的动作干预，不是同需求节能对照，不用于拟合或选模分数；只能检查开发模型的响应方向与幅度门。

## 数据与指标的确定解释

真实引擎只初始化四个允许回合；每个回合仅读取本回合起止内的原生点及完美天气/日程预报。每步31点/30秒，验证单位、实际动作、非负电功率、停止带和原生积分，结束核对官方KPI。失败时保留有效前缀和已尝试动作计数，停止后续运行，不重试advance或追加回合。

供热工况按当前已观测端点供热及过去4步启停，使用C1的互斥active/idle/transition。事件组按当前或过去1小时内真实账本/实际动作标记；边界两端包含。替换只在旧请求仍有效时计数；回基准必须由有有效请求变为无有效请求。冲突/不可行裁决标签只在首次确认版本时发出，不把每个保持步伪造成新裁决。rise/fall为当前已下发动作相对上步变化>0.1K。每个时域独立采用16步历史、步长4且预测终点不越回合。

多步评估是给定后续实际动作和完美预报的**离线条件预测**，不是声称在线控制器预知未来请求。模型不读取需求账本或未来真实温度/供热；动作序列作为条件输入，未来标签扰动不能改变预测。温度指标是端点误差，电量为窗累计，功率为逐900秒平均值。idle功率偏差指idle起点的整个预测窗，不能解释为所有未来时刻都保持空载。

## 执行顺序与停止

1. 核对C1锁、旧参照权重和当前时间登记；运行离线事件/预算/边界测试后，生成本轮freeze，锁定事件、采集/分析源码、协议和训练来源。freeze之后才允许真实初始化；输出目录必须新建，不覆盖旧工件。
2. 只执行上述464步以内的采集，登记用途和原始摘要；采集器没有校准/测试入口，API调用账本独立核对初始化时间及forecast/results边界。
3. 先检查新开发集12组×4时域的起点/日期门。缺任一必需单元时停止候选开发：重拟合0次，仅冻结参照和保持参照作失败诊断；不为取得资格浪费拟合预算或补日期。因果/支持/响应/数值门仍照实报告。
4. 只有覆盖全过才允许同结构一次重拟合：只读原6支训练＋新224，复用原greybox拟合及原expanded_baseline的非负空载/门控功率形式，残差alpha10、权重1、RC max_nfev150固定，不调用旧solar选模/标定入口。原模型、旧裕量与数据不改；新模型不生成裕量。候选最多2名，保持参照不计候选。
5. 新287按C1全门选择；全部条件未满足则写`closed_negative`，本轮采集/拟合入口关闭，仅保留verify/报告。无候选全过不能进入D或任何校准/盲评。若全部通过，仅记录开发资格；本次用户明确禁止触碰校准/测试，仍不自动进入E。

原子保存/调用日志/摘要验证属于完整性检查；独立重新计算现有输出不计新拟合或新FMU动作。不重新跑物理回合来改善结果。实现错误的修复必须保留失败输出与源版本，不改模型参数、事件、门槛或数据角色；若影响物理动作/标签，则停止而不额外重采。
