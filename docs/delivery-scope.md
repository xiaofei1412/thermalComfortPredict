# V1.0交付范围与A阶段资产边界

确认日期：2026-10-27。面向本人操作、研究复核和求职演示，固定为本机、单操作者、住宅单热区、供暖设定值、电能与操作温度。A阶段核查交付条件，不新增训练、算法、建筑或研究留出。

## 功能与使用资格

| 功能 | 输入与输出 | 当前交付及验证入口 |
| --- | --- | --- |
| 启动/退出 | Python环境、源码目录、端口 → 本机网页 | `start_workbench.ps1`；支持`.venv-cpu`/`.venv`或指定解释器，同工作区重复启动复用；Ctrl+C退出 |
| 真实仿真 | BOPTEST0.9.0、住宅场景 → 初始化测量 | 需要已部署的WSL/Docker服务，模型/源码摘要由部署脚本校验；启动网页不自动获取worker |
| 按需求/手动/演示规则 | 显式供暖意图、基准、裁决 → 映射目标、限速动作、实际温度/功率 | B接通确定性共同区间、冲突/不可行阻止推进、撤销/过期；手动/规则明确旁路。18～23.25°C、0.5K/15分钟，不承诺个人舒适 |
| 保存与结束 | 逐步真实响应 → 原生轨迹、累计指标、KPI核对 | 每个成功步保存；过期会话仅保留有效记录，不伪造缺失的最终KPI |
| 回放与导出 | 本地JSON → 历史时间点/完整记录 | 只读，不恢复FMU；异常/未完成记录明确标识；首次拉取仓库没有旧会话 |
| 同起点对照 | 已正常完成的源会话 → 重新初始化的规则轨迹 | 核对起点、时长、外生条件及相同需求快照/期限；规则不采纳需求，不能视为等需求满足的节能评估 |
| 研究证据 | 已归档报告 → 原结论和边界 | 人员预测、住宅MPC和办公室负结果可阅读；办公室后端仍拒绝新建 |

本轮范围不含MPC/人员模型的在线控制接入、多用户服务、3D/座位温差、开窗/制冷/风量控制、真实设备同步或真实Sim-to-Real。B工程接入已完成，证据见[B报告](../reports/demand-b/REPORT.md)；后续C～E按ROADMAP推进，是否授予控制能力由实验门决定。

## 十分钟演示流程

前提：Python依赖和BOPTEST已就绪；首次下载/构建不计入十分钟。

1. 0～1分钟：启动网页，确认场景、版本边界和实时/历史标识。若只做回放，需事先生成并保留会话。
2. 1～3分钟：新建住宅，默认按需求，提交A更暖/B更凉，观察冲突阻止推进；显式选择A后推进15分钟，观察请求/下发/实际温度的区别。
3. 3～5分钟：撤销B或等待仿真期限，检查裁决失效/恢复共同目标；展开目标区间提交26°C，观察不可行阻止推进。修改后可快进、步后暂停，解释热惯性；不声称自动满足真实人员需求。
4. 5～8分钟：正常结束保存，运行同起点规则对照，说明日程越界与人员满意不是同一指标。
5. 8～10分钟：拖动历史记录，导出JSON，查看办公室封存边界；说明断线/会话过期时为何不能继续冒充实时控制。

## 资产复现层次

机器清单在[delivery_assets.json](../configs/delivery_assets.json)，执行`.venv-cpu/Scripts/python.exe scripts/audit_delivery.py`可重新扫描；脚本只用Python标准库，不训练、不启动仿真、不改冻结工件。它记录来源、许可状态、位置、Git收录情况、文件大小和原始SHA-256，按相对路径及文件摘要形成目录摘要；它不是发行授权证明。

| 层次 | 必要资产 | 获取/重建方式及边界 |
| --- | --- | --- |
| 工作台源码运行 | 工作台Python/网页、NumPy/Pandas及相关证据报告 | Git源码目录与文档环境；不需要ASHRAE数据、训练权重或旧`outputs/`。已做最小源码隔离启动，但复用既有依赖，完整新环境验收留给F |
| 住宅实时仿真 | 固定BOPTEST源码/FMU、worker/web镜像、Redis、MinIO/mc构建源码 | `setup_boptest.ps1 up`按固定提交/摘要获取；模型年内日程/天气在FMU内，非实时天气API |
| 旧监督学习复现 | Git内历史CSV、字段/切分/配置、训练环境，派生表/权重 | `thermal_comfort prepare/run`及原基线协议；精确上游CSV发行版仍未确认，不可静默换成官方新版本 |
| 旧住宅动态模型/MPC复现 | 激励、恢复补采、太阳工况轨迹、selected模型和冻结清单 | 按原动态/恢复/太阳协议分阶段采集拟合；不是执行一个启动器就能恢复。旧测试角色不重置 |
| 办公室封存复核 | 原模型、协议锁、上游冻结链和closure | 当前工作区只读核验；历史复现另用工作区与原协议，不在本轮重启已封存攻关 |
| 历史会话/原始证据 | 本机`outputs/`中的原始轨迹和元数据 | 保留原文件与摘要；重跑只能生成新ID/时间戳，不能声称重建原会话身份。Git内紧凑报告不替代完整本机档案 |

研究复现命令分别见[基线](experiments/baseline.md)、[动态采集](experiments/dynamics.md)、[恢复模型](experiments/recovery_mpc.md)、[太阳模型](experiments/solar_mpc.md)和[冻结泛化](experiments/generalization.md)。带joblib/神经网络权重的历史工件只从自己的可信重建或档案加载。

## A阶段发现的发布缺口

| 编号 | 缺口 | 当前处置与后续责任 |
| --- | --- | --- |
| F01 | 根目录没有代码LICENSE；本地历史CSV准确发行链未闭合 | 不替作者选择许可证、不声称统一授权；F发布前确认代码许可及历史数据分发范围。工作台可在不使用该CSV的情况下运行 |
| F02 | 直接Python依赖已固定，但完整传递依赖和辅助provision构建未全部锁定 | 记录现有环境/源码/镜像摘要；F补干净依赖安装及部署验证，不承诺逐字节重建整个辅助链 |
| F03 | 旧权重/完整轨迹/冻结链仅在本机`outputs/` | A记录实际位置与摘要，列明重建顺序；F决定可获取的备份/资产包。尚无本阶段验证过的异地备份，不上传未确认可分发资产 |
| F04 | 当前是源码目录运行，wheel未包含根目录网页/报告 | 明确只支持源码工作区和editable安装，不宣称任意目录下wheel可运行；F再决定是否制作独立安装包 |
| F05 | 新拉取仓库无历史会话，离线回放不是开箱自带示例 | 先通过真实仿真生成；F准备来源/使用条件明确的紧凑回放样例，不伪造测量 |

这些是F阶段必要交付补项，A只完成审计与缩小声明；不将A完成写成V1.0已发布或所有研究已复现。B阶段仍只处理需求协议，不自动扩算法或办公室场景。
